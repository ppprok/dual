# Как заводить задачи

Задача пишется для того, кто возьмётся за неё **через месяц и без вас**: зачем она, как понять, что
готово, и обо что можно споткнуться.

## Шаблон

```markdown
## Контекст
Зачем задача существует: 1-3 предложения. Откуда пришла, что будет, если её не сделать.

## DoD
Что мы увидим, когда задача сделана, — проверяемо:
- артефакты (код в ветке, тест, библиотека/обёртка, отчёт по эксперименту);
- измеримые критерии, где применимо (число покрытий на тестовой матрице, время перечисления ≤ X);
- для исследования: что считаем подтверждением гипотезы, что — опровержением.
В объём не берём: …

## Как планируем решать
Тезисный план (для мелких задач — 1 предложение). Развилки, которые придётся выбирать по дороге.

## Ограничения и зависимости
Блокирующие задачи (`#N`), внешние зависимости, решения, нужные от владельца.
```

## Как заполнять

- **Контекст** — последствие бездействия, а не важность.
- **DoD** — главный раздел. Для алгоритмов дуализации гарантия обычно проверяется тестом на матрице
  с известным числом минимальных покрытий (`src/tests/data/*.hg`, имя `rows_cols_count`): формулируйте
  гарантию («RUNCM находит ровно 275 покрытий на `15_20_275.hg` при порционной выдаче»), а не реализацию.
  Отдельно называйте, что НЕ входит.
- **Как планируем решать** — ценность в развилках: назовите их, чтобы исполнитель не решал молча.
- **Ограничения** — необратимое или внешнее (публикация, смена API `librunc.so`, на который завязан
  Python-код) — это блокер, видимый до начала работы.

## Команда

Тело — в файл, JSON собирать Python-ом (см. скилл `github`):

```bash
TOKEN=$(tr -d '[:space:]' < .github.token)
python3 -c 'import json;print(json.dumps({"title":"Короткая суть задачи","body":open("body.md").read()}))' > issue.json
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/ppprok/dual/issues -d @issue.json \
  | python3 -c 'import json,sys;d=json.load(sys.stdin);print(d["number"],d["html_url"])'
```

**Номер задачи берите из ответа** — не по памяти и не «следующий»: issue и PR на GitHub делят нумерацию.

## Связь с остальным флоу

Задача заводится **до** ветки: ветка `type/taskID_description`, коммиты `[#taskID] type: Description`,
в теле PR `Closes #taskID` (скилл `github`). Задача без исполнения — нормально; ветка без задачи — нет.
Большое — зонтичной задачей со списком срезов; каждый срез полезен сам по себе.
